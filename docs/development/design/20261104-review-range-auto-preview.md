# 创建审查时自动预览范围

## 背景与决定

原创建窗口要求先点击“预览范围”，再点击“创建审查”。后端用预览中的源/目标 commit OID 校验分支是否变化，以避免创建范围与用户看到的范围不一致。这个一致性约束继续保留，但预览计算由界面自动触发。

用户已确认采用自动预览交互。本次只调整创建流程，不改变审查范围计算、投影构建或保存机制。

## 交互与边界

- 打开创建窗口、切换源或目标分支时，自动计算并显示基准、源 commit、提交数和变更文件数，移除手动预览按钮。
- 计算期间禁用创建；预览成功且标题不是空白时允许创建。修改标题不重新计算范围。
- 预览失败在窗口内显示原因和重试按钮；重新选择分支也会重新计算。
- 每次计算使用递增请求序号，旧请求的成功和失败结果均不得覆盖新选择；关闭窗口使未完成的预览失效。
- 创建期间锁定标题、分支和创建入口，避免重复提交或改变正在提交的输入。
- 创建仍使用已展示预览，并保留后端构建前后的分支 OID 校验。`review.ErrBranchesChanged` 经 HTTP 映射为 409 和 `code: branches_changed`。前端收到后自动获取新范围，提示确认后再次创建，不自动重新提交。

预览负责解析和展示候选范围；创建负责重新校验候选并构建、保存审查。前端协调交互状态，不承担 Git 范围校验。

## 验证

- `node --test internal/transport/web/app_test.cjs`：使用 Node 内置测试运行器和模拟 DOM/fetch 执行完整页面脚本，验证自动预览、标题修改、异步响应乱序、关闭重开、失败重试，以及分支变化后必须再次显式提交。
- `go test ./internal/transport/web ./internal/app/review ./internal/app/capture`：覆盖 HTTP 过期预览的结构化冲突响应及现有范围校验、审查和采集行为。

## 创建表单反馈与布局

按用户反馈补充以下行为：打开窗口时聚焦标题，标题标注必填；首次失焦后若标题为空或只有空白，显示红色边框及“请输入审查标题。”，填写有效内容后立即清除。提示通过 `aria-describedby` 关联输入框，并同步 `aria-invalid`。重新打开窗口重置失焦校验状态。

弹窗最大宽度由 620px 增至 820px；分支标签和选择框允许收缩，避免长分支名的固有宽度撑破弹窗。540px 以下改为上下排列，预览文字允许换行，确保窄屏下不产生横向溢出。

补充验证：前端 5 项测试及 Web 包测试通过。独立无头 Chrome 使用模拟接口和长分支名验证桌面 1280px、窄屏 390px：标题初始焦点、失焦错误、实际红色边框、输入后清除提示均正常；两种宽度下弹窗 scrollWidth 均等于 clientWidth，页面也无横向溢出。浏览器检查使用临时文件，不写入项目。
