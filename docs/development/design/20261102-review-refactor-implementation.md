# CR 重构实施记录

实施基线：`bebe21c`。依据用户授权的[重构方案](20261102-review-refactor.draft1.md)。本记录描述本次代码结果；早期实现对齐记录中的验证不作为本次证据。

## 范围与读取

- `review.CommitRange` 使用完整源/目标 commit OID；`PreviewRange` 和 `Create` 支持不带分支的范围。`BranchTracking` / `ResolveTracking` 只负责解析更新候选。HTTP 创建仍要求分支。
- 分支解析、投影构建和发布分开。两端成功解析且构建成功后，短事务原子更新 OID、提交集合和审阅项；发布前再次检查跟踪分支。引用与数据库不能跨系统原子提交，发布代表捕获的 OID 对。
- POST refresh 显式更新；列表、GET 详情、diff、评论与审阅写入不隐式刷新。前端打开详情时先请求更新；失败时读取已保存的 commit 范围并显示提示。
- 源/目标分支缺失不修改原范围、投影版本、审批或评论。列表仅恢复摘要，不读取 Git 或快照；详情元数据和非映射评论列表也不依赖内容对象。真正依赖缺失对象的 diff/行映射仍显式报错。
- 输入签名覆盖两端 OID、三点比较模式、来源 Generation 和投影算法版本。相同输入不重建；同 commit 上删除/重建 batch 仍触发更新。
- 批量决定在一个事务内检查完整选择与版本并写入；评论和回复携带版本。离开当前视图的项不能通过旧页面继续回复。保留旧线程无 anchor_item 的兼容读取。

## 存储与领域边界

- schema v7 在 v6 基础增量增加输入签名、比较模式、历史诊断和独立刷新状态。v1 fixture 经 v6 再迁移 v7，原始事件、审批、评论和旧项身份继续保留。
- 刷新 attempt 独立于投影版本；较旧 attempt 的完成不能覆盖较新 attempt 的结果。刷新错误不会将 CR 审阅状态改成错误或清空。
- `pkg/change` 提供独立的 File/State、原始路径 JSON 编码及精确状态转换；Store 兼容别名保留既有调用和存储格式。
- `preparedIO` 在事务前解析 Git 基准、旧快照并验证内容；事务内只使用准备好的状态，缺少输入即报错，不回调 Git。采集、历史改写、审阅发布均采用此路径，并保留原有 cursor/revision/幂等检查。
- 审阅元数据在一致事务内读取，快照通过固定的不可变引用在事务结束后恢复。源事件成员改为批量查询。
- 事务内仍保留本地 blob 的存在性元数据检查，避免另一个项目卸载独占内容后，已准备的捕获写入悬空引用；不在事务内重新读文件内容或计算内容哈希。项目删除的文件移除/回滚行为保持原有机制。
- 基准读取注册接口保留为准备阶段的兼容适配层；没有为每张表新增仓储抽象，也没有全仓改包名。领域转换与跨行约束仍由现有 capture/review/store 用例协作完成。

## 内容读取与诊断

- Tree 使用 ls-tree 加一个流式 cat-file 批处理，逐对象注册内容身份，不同时保留整仓文件字节。相同 OID 在进程中复用树。
- 树缓存最多 16 项、合计 100000 文件项；Git 内容缓存最多 32 MiB、单项最多 4 MiB。diff/行映射分别采用有容量上限的结果缓存，错误不缓存。缓存可丢弃，不作为持久化历史。
- 原始路径字节、mode、符号链接、二进制和 gitlink 语义不变；未变 Git 字节没有复制入 Motif 持久 blob。
- `closure` 表达最终状态闭合，`history` 表达已纳入记录的归属情况；结构化 diagnostics 保留来源未知、投影冲突与末尾补齐。旧 `integrity` 字段保留兼容。“complete”不承诺真实开发过程没有漏采。
