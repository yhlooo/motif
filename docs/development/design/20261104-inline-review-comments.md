# 行号旁输入与行下讨论

## 用户决定和边界

用户要求点击代码行后就近输入评论，评论与回复显示在指定行下方，避免到内容顶部或末尾寻找评论。

本次调整 Web 展示及交互，不改动评论持久化、锚点语义、映射算法或审查范围校验。已有 old/new 侧、mapped_path 与 mapped_ranges 是展示依据，不用原始行号猜测当前位置。DOM 焦点与定位调查见 [研究记录](../research/20261104-line-comment-positioning.md)。

## 输入浮层

- 移除顶部 composer 容器。点击行号后在其旁边创建 fixed 浮层，挂载 body，自动调整水平位置及上下方向，限制在视口内，不受 diff 滚动区裁切。
- 输入框自动聚焦且 preventScroll，不滚动页面。Shift 点击同侧另一行扩展范围时保留草稿并更新位置及高亮。
- 浮层跟随页面、diff 内部滚动和窗口尺寸变化定位；锚点离开代码可视区时暂时隐藏，保留草稿。
- 支持取消、Escape、Ctrl/Cmd+Enter 发表；关闭时可把焦点交回行号且不滚动。切换批次/审查范围时清理浮层、监听器及选中高亮。
- 输入错误、提交失败在浮层内显示，保留草稿。已保存但评论重新读取失败时，只允许重新加载，避免重试重复发表。

## 行内讨论

- 渲染 diff 时保存按原始路径、old/new 侧和行号查找代码行的索引。
- 单行评论显示在对应行后；范围或映射后多个范围的评论只展示一次，放在最后一个仍可见的范围行之后。同一代码行的多个讨论共用行下容器。
- 使用 mapped_path 处理重命名、mapped_ranges 处理位移与部分删除。若对应行未被当前 diff hunk 展开，评论保留在该文件内并明确标注，不能静默丢弃；若该文件无净 diff，则建立带文件标题的评论区。
- 已有评论正文就地显示，点击“回复”展开该讨论下的输入区。评论文字均通过 textContent 渲染。
- 创建/回复后只重新请求映射后的讨论并替换行内讨论节点，不重新读取和渲染 diff，不重建文件树。保留页面及 diff 内部滚动位置和目录折叠状态。
- 评论请求绑定 review、projection、view_version、当前连续项范围及渲染代次，丢弃过期返回，写入仍携带原后端版本校验。并发评论读取仅应用最新结果。

## 验证

- 13 项前端测试通过，新增 old/new 侧、映射范围末行、重命名后的文件归属、未展开行的评论保留，以及过期视图隔离测试。
- 现有 Web 评论/回复 API 测试及评论插入、删除、改名映射测试通过；JavaScript 语法检查及 git diff --check 通过。
- 实时无头 Chrome 在 1440px 和 390px 下执行完整交互：深处代码行打开浮层不跳动且浮层不出屏，Shift 范围保留草稿，评论出现在末行下方，旧侧和改名映射正确，回复原地完成，diff 节点及文件树折叠状态保留，Escape 和批次切换关闭浮层。
- 浏览器模拟保存成功后首次读取失败：重试只读取，POST 次数仍为 1。发表评论与回复前后，文档和 diff 内部滚动位置保持不变；长代码行下讨论宽度受限，无横向页面溢出或脚本异常。
