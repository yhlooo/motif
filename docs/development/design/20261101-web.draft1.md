# 本地 Web 审查工作流

状态：讨论草案，不作为实现依据。配套文档：[采集](20261101-capture.draft1.md)、[整理](20261101-organization.draft1.md)。

## 已确认的方向

- 一期提供纯本地的查看及操作界面，入口为 `motif web`。
- 延续总体设计，以意图批次为主要审查视角，同时能追溯实际代码差异和原始修改记录。

“纯本地”是否只限制数据存储与 Web 服务，还是也限制整理所使用的模型，需要进一步明确；暂不假定必须使用本地模型。

## 待讨论的用户流程

选择仓库 → 选择提交范围或未提交修改 → 查看最终差异与采集覆盖情况 → 触发或读取整理结果 → 按批次审查 → 查看来源与记录审阅状态。

这是流程提案，尚未确认一期支持的全部操作。

## 下一步逐项细化

1. 页面与状态：仓库入口、范围选择、生成进度、批次列表、diff、原始记录、缺失及错误状态。
2. 操作边界：审阅标记、评论、重新整理、拆分合并、重新归属、反馈给 Agent；逐项确认是否进入一期。
3. 数据契约：查询、分页、内容加载、任务进度、写操作并发及版本冲突。
4. 启动：监听地址、端口冲突、浏览器打开、退出、重复启动、后台工作与进程归属。
5. 本地访问保护：来源校验、跨站请求、代码内容转义；浏览数据与执行 Agent 的权限边界。
6. 实现：前端技术选择、Go 内嵌资源、开发与分发方式。
7. 验收：新仓库无记录、无采集历史的 diff、生成失败、中途退出、结果过期、大 diff。
