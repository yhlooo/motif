# 状态、事实与投影重构实施记录

基线：`b2f7b56`；工作分支 `refactor/state-facts-projections`。依据用户授权的[重构设计](20261102-architecture-rebuild.md)。本记录只使用本次实际执行的验证，不继承此前实施记录的结论。

## 实现结果

- `internal/domain` 定义独立领域值、纯 CapturePlan 规划器与纯投影组装器。领域不导入 GORM、Git 进程或 HTTP。采集、改写、审阅用例在 `internal/app`，Git 和数据库在 `internal/adapters`，入口在 `internal/transport`。
- GitReader 不再依赖数据库或注册内容回调。`workspace.Project` 是应用层装配对象，组合独立 GitReader 和元数据适配器。
- File 使用 ContentRef 定位字节：Git 引用编码仓库位置及 OID，本地内容使用 SHA-256。ContentID 独立表达仓库对象格式下的字节身份，避免相同内容的 Git/本地引用产生伪变化。评论也保存完整内容引用。
- State 为结构共享的不可变 AVL 路径索引。Clone 只复制根引用；每次更新复制搜索路径，快照保存持久根，节点内容寻址。原始非 UTF-8 路径、mode、符号链接、二进制、gitlink、coverage 继续保留。
- Git Tree 只读取条目与 OID，不再批量读取全仓 blob。首次条目排序后一次建树；工作区观测从此前状态或 Git 基准更新，未变子树复用。diff 缓存直接用根身份定位，不序列化两份全仓状态建立缓存键。
- CapturePlan 在事务外计算快照、修改、调用转换、提交关联与游标结果。提交事务仅检查幂等回执、游标版本及约束并发布。准备状态显式传入，不使用 context 隐式传递 IO 能力。
- 修改事实不再保存可更新的 final_commit 列。commit_changes 保存提交关联，rewrite_derivations 保存来源边；原始与派生事件拥有独立序列空间。RewritePlan 发布校验来源 revision 和 cursor，文件重放、合并及内容准备均在事务外。
- CR 每次发布插入不可变投影，再切换当前投影 ID。不再修改旧项 active 标记、搬动历史 position 或覆盖旧快照。稳定身份与 decision 分开保存，历史投影可按 ID 读取。
- HTTP/前端 diff 与评论映射可固定 projection_id；旧投影读不受新发布覆盖。写入要求当前 view_version；批量审批额外使用逐项 decision revision，防止同一代码版本下丢失并发决定。选择 diff 仅恢复两端，行映射恢复选择内部，不恢复无关项。
- 来源 revision 改为每仓库维护；重复回执、无变化观察、其它项目采集和审阅决定均不使当前来源失效。自动 unknown 组成员变化纳入审阅身份指纹。
- 对象持有关系按项目登记，子树已被本项目持有时准备阶段停止遍历。共享租约覆盖发布，卸载持排他租约；锁在进程间有效。数据库删除后，独占对象通过可恢复任务清理；启动重试未完成任务。共享节点及内容继续保留。
- 新数据库格式为 8。不提供旧格式迁移、旧项身份匹配或旧快照读取。发现旧库直接报错；不会自动删除开发数据。删除了旧兼容 fixture。Go 依赖版本及 go.sum 未变。

## 与初稿的具体取舍

采用持久化 AVL 路径索引，未实现初稿的目录 overlay/Git 子树惰性节点混合模型。这样可集中验证结构共享和精确状态转换，避免引入两类树的合并规则。

代价是初始基准路径元数据会建立本地索引，首次冷恢复读取该根包含的节点。后续快照共享节点，未变 Git 文件字节仍直接依赖 Git。尚未实现完全按路径惰性的冷恢复；工作区快照也仍需扫描文件内容。这些成本没有用缓存命中或微基准掩盖。

SQLite 仍在事务内验证批次跨行规则、创建派生元数据和维护关联；纯领域规划负责文件状态转换与投影组装。没有为每张表添加仓储接口，也没有建立空的 ports 框架。

## 验证

本次重构前的原全量测试先运行通过，再实施替换。删除的测试仅针对已经明确取消的旧库/旧项兼容和 Git 回调机制；采集、分批、部分提交、改写、安装卸载、审阅、评论及 HTTP 主流程回归保留。

新增覆盖：

- 2000 次随机状态更新与独立 map 参考模型对照，旧根不变，原始路径 JSON 往返。
- 1000 路径状态更新一条路径，新增持久节点不超过 20；清空缓存可恢复，损坏节点报错。
- Git/本地内容无登记、跨实例读取；混合引用身份一致；缺失 Git 对象和损坏本地字节报错。
- 新投影发布后旧投影保持原内容，同身份审批保留，旧版本写入拒绝。
- 单项 diff 不访问被故意破坏的无关项状态；需要该状态的读取明确失败。
- 幂等回执、不变观察、跨项目采集的来源 revision 不变；冲突回执失败。
- 同代码版本下过期 decision revision 拒绝，批量决定不部分覆盖。
- 删除等待活跃共享租约；共享节点和字节在另一个项目卸载后继续可读。
- 旧格式拒绝且不迁移原版本。

执行检查：

- `CGO_ENABLED=0 go test ./...`、`go test -race ./...`。
- `go vet ./...`、`node --check internal/transport/web/assets/app.js`、`git diff --check`。
- 纯 Go Linux amd64 与 macOS arm64 编译。
- 真实二进制在临时 Git 仓库安装项目 hooks：输入 PreToolUse/PostToolUse，修改文件，Stop 要求分批，CLI 创建 batch 后 Stop 放行，实际 Git 提交触发关联。
- 系统 Chromium / Playwright：创建 CR、选中 AI batch、批准、行评论、回复、删除两端分支后刷新失败仍读取已保存评论、390px 窄屏。页面脚本错误 0。
- HTTP 回归额外检查按旧 projection_id 读取旧 diff，新投影内容不混入。

真实 hook 验证使用协议输入，不是实际 Codex 模型会话。安装诊断在该隔离环境报告 CLI 状态不可诊断，没有将其写成 Codex 全链路成功。所有临时仓库、数据库、二进制与浏览器产物均在仓库外。

## 性能样本

Linux amd64 / AMD EPYC 9V74，`-benchtime=10x -count=1`。低样本微基准，不是旧版本对照或大仓库压力测试；执行环境也与旧记录不同。

| 操作 | 规模 | 单次耗时 | 分配/进程 |
|---|---|---:|---|
| 单路径不可变更新 | 100 路径 | 9.8 µs | 4520 B / 49 次分配 |
| 单路径不可变更新 | 10000 路径 | 16.9 µs | 9168 B / 98 次分配 |
| 新 Repository 读取 Git 树 | 100 文件 | 8.3 ms | 1 个 Git 进程 |
| 新 Repository 读取 Git 树 | 1000 文件 | 20.1 ms | 1 个 Git 进程 |
| 已缓存 Git 树 | 100/1000 文件 | 1.1 / 0.54 µs | 0 个 Git 进程 |

单路径更新的分配量随树深增长，没有按 100 倍文件数复制 100 倍状态；独立持久化测试验证实际新增节点数。冷树样本只包含树元数据，不含文件字节；warm 样本不代表跨进程 hook 启动时间。没有据此承诺端到端加速倍数。

## 保留边界

串行采集、Git 对象可用性、无常规 GC、无法证明来源时 unknown 的产品边界保持。大仓库冷启动与跨进程观测延迟需要后续针对真实仓库测量；本次已实现的结构共享不等于所有读取成本都只与修改数相关。

环境使用 `/tmp/go/bin/go` 1.26.2。SQLite 默认模块下载跳转被网络策略拒绝，本次从官方 GitLab 固定 v1.23.1 标签建立临时模块代理，Go 按原有 go.sum 校验通过，未修改依赖或引入源码副本。
